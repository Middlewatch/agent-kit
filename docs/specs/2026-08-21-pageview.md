# pageview

Date: 2026-08-21   Status: done

## Problem

Agents on this estate generate browser artifacts on headless machines: interactive HTML lessons from the `teach` skill, HTML design mockups a session is iterating on, SVG diagrams, PDFs. Markdown the owner reads in a text editor; everything else needs a browser, and this extension is the route to one. There is no display, so `xdg-open` fails, and the agent falls back to printing a file path the owner cannot click. Today the workaround is manual: start `python3 -m http.server`, work out the tailscale IP, and type the URL by hand. The `teach` skill currently documents this workaround as a caveat.

## Outcome

During a pi session on a headless tailnet machine, when the agent writes `lessons/0001-intro.html`, the extension announces `http://<tailscale-ip>:8722/lessons/0001-intro.html` in the TUI and to the agent. The test: `curl` of that URL from a tailnet client returns the file byte-identical; `curl` against `127.0.0.1:8722` and the LAN interface is refused; after the session exits, the port no longer accepts connections.

## Non-goals

- **`tailscale serve` integration.** Stable HTTPS URLs are nice, but it mutates tailscale state, needs operator permissions, and outlives the session. Rejected in grilling.
- **Serving beyond the session.** The server dies with pi. A later session re-serves with one command.
- **TLS or auth.** The tailnet is the security boundary.
- **LAN exposure.** Tailnet interface only, owner ruling.
- **Markdown rendering.** The terminal already handles markdown; this extension is for content only a browser can render.

## Decisions

Settled with the owner 2026-08-21:

- **Trigger**: auto-detect plus manual. The extension watches tool events; when the agent writes a `.html`, `.htm`, `.svg`, or `.pdf` file under the session cwd, it serves and announces the URL. A `/serve <path>` command covers everything else. Other file types are not announced but remain reachable as assets once the server is up.
- **Server**: in-process static HTTP server inside the extension. Started lazily on first trigger, closed in an idempotent `session_shutdown` handler.
- **Bind address**: the tailscale interface, discovered at runtime (`tailscale ip -4`, falling back to interface lookup). When no tailscale interface exists, bind `127.0.0.1` and say so in the notify, since an SSH port-forward still makes that useful. When `DISPLAY` is set, additionally attempt a local `xdg-open` of the URL.
- **Docroot**: the session cwd, so relative links (`../assets/`, sibling lessons) resolve. Requests that escape the docroot via `..` or symlinks are refused. `/serve` on a path outside cwd is refused with a message rather than widening the docroot.
- **Port**: base 8722, incrementing on conflict so concurrent sessions coexist and URLs stay predictable.
- **URL delivery**: `ctx.ui.notify` for the owner and context injection for the agent, so replies can cite the real URL instead of a file path.
- **Live reload** (owner ruling 2026-08-21, for design-iteration sessions rather than teach): the server injects a small script into served HTML that listens on an SSE endpoint; the extension watches files it has served and pings reload on change. Injection applies to HTML responses only, so served SVG/PDF bytes stay untouched. The URL is the seam: a page fetched through the server reloads itself, the file on disk carries no trace.
- **Home**: `extensions/pageview/` in agent-kit with its own README and vitest suite, entry point registered in the kit `package.json` under `pi.extensions`, deployed by the existing pi-package mechanism. Follows the `pi-scratchpad` layout.
- Once built, the `teach` skill's headless caveat is replaced with a pointer to this extension (same commit as the slice that lands auto-detect).

## Seams under test

- **Server module**: given a docroot and bind address, serves files with correct MIME types, refuses docroot escapes, picks the fallback port. Driven directly by vitest, no pi runtime needed. Prior art: `extensions/pi-scratchpad` (`npx vitest run`).
- **Trigger filter**: a pure function from tool event (tool name, file path, cwd) to serve-or-ignore, unit-tested over the extension list and out-of-cwd paths.
- The pi event wiring itself stays thin and is exercised manually (`/reload`, write a file, click the URL), per the kit's rule against ceremonial harnesses.

## Open questions

- 2026-08-21, with S3: the Outcome's byte-identical claim now holds for non-HTML responses; HTML carries the injected reload script, per the ratified live-reload decision. Files on disk are unchanged either way.

- Name. `pageview` is the working name; `peek` and `serve` were candidates. Owner picks before S1 lands.
- Resolved with S4: neither block nor annotate. On a headless machine a bare single-file `xdg-open`/`open` bash call is rewritten in place into an `echo` of the served URL, so the call succeeds and the URL reaches agent and owner. Compound commands and `DISPLAY` machines are untouched.

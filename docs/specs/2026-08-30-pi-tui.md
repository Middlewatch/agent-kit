# pi-tui

Date: 2026-08-30   Status: done

## Problem

Pi is the daily driver now that evoker is frozen, and the stock TUI is the
last friction: tool results render as solid green or red blocks that bury
the output, the footer packs unlabeled numbers and extension chatter into
three cryptic lines, startup is a plain text dump, and editing estate files
(skills, prompt templates, the system prompt) means leaving the session.
The owner's own extensions add to the noise with menus and status strings
that were never given a layout pass.

## Outcome

Launch pi in any workspace on this machine and: the header is a centered
fade-style pi glyph over live estate facts; every built-in tool call
renders gutter-style with no background fill and a one-line status summary;
the footer is three labeled lines (location, session, extensions); colors
follow the modus-vivendi-tinted palette the owner runs everywhere else; the
todo list and working indicator are visible at a glance; and `/edit` opens a
picked skill, prompt template, or system prompt file in neovim on its real
path and resumes the session cleanly on exit. Component render output is
covered by unit tests; the final acceptance is the owner driving one
session and finding no regression in scrollback behavior.

## Non-goals

- **Click-to-move-cursor.** Requires upstream mouse routing in pi-mono;
  the owner dropped it.
- **Replacing built-in menus.** Model picker, command palette, and session
  selector are not extensible surfaces, and the owner has no complaint
  with them.
- **Modal editing.** No typing complaints surfaced; the stock editor plus
  ctrl+g covers composition.
- **Upstream PRs.** Everything ships as extension and config in this repo.

## Decisions

- A `modus-vivendi-tinted` pi theme: all tokens mapped semantically from
  the published modus palette (Protesilaos Stavrou's modus-themes), the
  required background tokens set to its subtle surface colors so the
  owner's terminal-level background and opacity stay visible. Tracked in
  the kit and linked into the pi themes directory via `deployments.json`.
- One extension, `extensions/pi-tui`, registered in the kit `package.json`;
  README, tests, and design doc in its directory per the extensions index.
- Tool rendering overrides the built-ins by name (`bash`, `edit`, `read`,
  `write`, `grep`, `find`, `ls`) supplying `renderCall`/`renderResult`
  only; built-in execution is inherited per pi's slot-resolution rules.
  Gutter style: status glyph + tool + args header, dim vertical gutter on
  output lines, closing line with status, duration, and hidden-line count.
- Footer replacement via `setFooter`, reading git branch and other
  extensions' statuses from `footerData` and token stats from the session;
  three lines — location, session (model, thinking, context, cache),
  extensions — every value labeled.
- Header via `setHeader`, centered against the render width: fade-glyph pi
  (solid roof, legs dissolving through shade blocks), then workspace and
  branch, then cheap estate counts (skills, extensions, inbox notes).
- Todo list as a `setWidget` above the editor; working indicator restyled
  via `setWorkingIndicator`.
- `/edit` command: SelectList picker over skills, prompt templates, and
  system prompt files, then spawn neovim on the real path using the same
  suspend/resume pattern as pi's ctrl+g external editor. If the S1 probe
  shows extensions cannot suspend the TUI safely, fall back to
  `ctx.ui.editor()` with ctrl+g and write the temp file back to the real
  path.
- The owner's other extensions get a menu and status cleanup pass in place
  (their own repos, their own commits), normalized to pi's documented
  patterns; pi-tui exports nothing to them.

## Seams under test

Component render output: every renderer (`render(width)`) returns plain
string arrays, so tests feed a fixed theme and width and assert on lines —
gutter framing, footer labels, glyph centering, truncation at narrow
widths. `/edit` write-back and file discovery are tested against fixture
directories. Prior art: the per-extension `npm test` suites in
agent-delegate, pageview, and pi-scratchpad. Live probes (scrollback,
suspend) are session walkthroughs with the owner, not automated tests.

  and loading (`pi --list-models` runs the factory with no errors).
  Empirical verdicts are NOT yet recorded — both probes need the
  owner's terminal. (b) has a strong static basis: the TUI interface
  exposes public `stop()`/`start()`, and pi's own ctrl+g editor uses
  exactly `ui.stop(); spawn(stdio:"inherit"); ui.start();
  requestRender(true)`, so S7 builds on that path. (a) has no static
  basis at all. The acceptance session runs `/pitui-probe-scroll`
  (scroll into history while it ticks) and `/pitui-probe-suspend`, and
  the pass/fail observations get recorded here.

  **Spec correction:** built-in tool *rendering* is inherited per slot,
  but `execute` is required on every registered tool — execution is not
  inherited. S3 delegates to `createBashTool()` et al. (the pattern in
  pi's `built-in-tool-renderer.ts` example), which is the same built-in
  implementation, so behavior is unchanged.

## Open questions

- Whether pi accepts a background token close enough to the terminal's
  own color to read as unpainted, or the theme needs the terminal hex
  verbatim — settled live in S2 against the owner's opacity setting.
- Which estate facts earn the dashboard line beyond skills, extensions,
  and inbox counts — settled live during S5.
- ~~Whether pi's Box wrapper still applies the tool background around a
  custom `renderResult` component~~ — answered in S3: with
  `renderShell: "self"` the ToolExecutionComponent renders the tool's
  components in a plain Container and never applies the background Box,
  so the theme's tool background tokens stay meaningful for other tools.
- ~~Exact semantics of the stock footer stats (the arrow/R/CH cluster)~~ —
  read from `footer.js` during S4: ↑/↓ are cumulative input/output
  tokens across all session entries, R/W cumulative cache read/write, CH
  the latest assistant response's cache-hit rate (cacheRead over its
  full prompt), and the percentage is context used over the window. The
  new footer labels them `in`, `out`, `read`, `write`, `hit`, and
  `ctx … of …`.
- ~~S8 inventory~~ — taken during S8. Statuses: pi-interlock
  (`Interlock: armed`), autojournal (`autojournal: syncing… Ns`),
  context-fold (`⧉ context-fold …`), agent-delegate (pool counters).
  Menus: todo's `/todos` viewer and agent-delegate's `/delegations`
  viewer, both already on the house press-any-key pattern;
  claude-go and sysprompt-editor publish nothing. Fixes: the footer now
  strips a status's redundant self-name prefix (covers interlock and
  autojournal with no change to their repos), agent-delegate's counters
  dropped their `delegates` prefix, and context-fold dropped its name
  from the fold status in its own repo (commit 53787d6 there).

- Before reading any skill or reference, classify the request: a conversation or question, a small change, a spec'd build, or research. A conversation gets an answer. A small change (a config edit, a script, a fix inside code already read) gets the change, one check, and a report. Only a spec'd build loads the build, spec, feature-map, and data-model skills, and only research loads deep-research. When the class is unclear, treat it as the smaller one and say which you chose.
- A skill or reference loaded for a task governs that task only; once the task class changes or the user says it no longer applies, it is inert text. When a loaded document and the most recent prompt disagree, the prompt wins: name the conflict in one line and continue.
- During a long turn, write one line when a slice starts and one when it lands, as task-list lines: `- [ ] slice` at the start, `- [x] slice` when it lands, `- [-] slice (skip: reason)` when dropped. The TUI progress widget reads those lines.
- Verify a delegate's material claims against the artifact (diff, file, runtime output) before repeating them.
